# tsai engineering quickstart

`tsai` is an Apache-2.0 Python library for classification, regression, forecasting, and related learning tasks over time-series and sequential data. It adds time-series data structures, preparation tools, model families, learner factories, callbacks, and experiment helpers to the PyTorch and fastai ecosystem (`README.md`, `pyproject.toml`).

The most important repository convention is that **the notebooks in `nbs/` are the editable source**. Most files under `tsai/` are generated by nbdev and begin with a pointer to their owning notebook. Read the Python modules for fast navigation, but make code, test, and API-documentation changes in the corresponding notebook; see the [development workflow](/openwiki/workflows/development.md).

## Install and verify

Python 3.10 or newer is required. Stable users install from PyPI; contributors use an editable install:

```bash
pip install tsai
# or, from a checkout
pip install -e ".[dev]"
nbdev-install-hooks
```

Optional integrations used by selected features are available through `pip install -e ".[extras]"`, although Optuna and W&B are currently not included in that extra. The authoritative dependency and packaging configuration is `pyproject.toml`.

A minimal import check is:

```python
from tsai.basics import *
```

`from tsai.all import *` exposes the broad package surface, including all models and integrations, while `tsai.basics` is a narrower common facade. These imports also apply fastai `Learner` patches such as `get_X_preds`; the [architecture overview](/openwiki/architecture/overview.md) explains the import layers.

## Canonical classification path

```python
from tsai.basics import *

X, y, splits = get_classification_data("ECG200", split_data=False)
learn = TSClassifier(
    X, y,
    splits=splits,
    arch="InceptionTimePlus",
    tfms=[None, TSClassification()],
    batch_tfms=TSStandardize(),
    metrics=accuracy,
)
learn.fit_one_cycle(10, 3e-4)
learn.export("classifier.pkl")
```

For inference:

```python
from tsai.inference import load_learner

learn = load_learner("classifier.pkl")
probas, targets, decoded = learn.get_X_preds(X[splits[1]], y[splits[1]])
```

The expected input convention is normally **`[samples, variables, sequence length]`**. `get_ts_dls` converts arrays into `TSDatasets` and `TSDataLoaders`; loader metadata then determines model input channels, sequence length, output count, and shaped target dimensions. Follow the full [data and learning flow](/openwiki/architecture/data-and-learning.md) before changing shape handling, model construction, or inference.

## Change checklist

1. Locate the generated Python symbol, then open the notebook named in its header.
2. Edit the notebook and add or update executable notebook tests and Markdown API documentation.
3. Regenerate modules with `nbdev-export`; never treat a direct `tsai/*.py` edit as the durable change.
4. Run `nbdev-prepare` on Linux/CI. On Apple Silicon with MPS-related worker crashes, use `nbdev-clean`, `nbdev-export`, then `nbdev-test --n_workers 0`.
5. For packaging changes, build the wheel and verify it outside the checkout so the source tree cannot mask missing files.
6. Inspect both notebook and generated-module diffs before committing.

## Current operational context

Recent history emphasizes compatibility and reliability rather than a new architectural layer: the 1.0 migration moved packaging to `pyproject.toml` and nbdev 3; follow-up fixes restored subpackages to built artifacts, reduced memory use in array creation, removed external downloads from default tests, initialized sklearn ROCKET pipelines correctly, made `Reshape` TorchScript-compatible, and added Optuna multi-objective handling. These changes make artifact tests, offline-capable tests, shape compatibility, and notebook/module synchronization high-value review areas.
